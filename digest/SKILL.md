# {{NAME}}

为{{DEPT}}医生每日精选最新文献：多源抓取 → 评分选文 → **你**生成中文速览 → 数字保真校验 → 日报。**全程无需任何 API key**（数据源公共、摘要由你完成）。

## 执行流程（严格按序）

### 第 1 步：抓取（确定性脚本，不要自己实现抓取）

```bash
python3 scripts/fetch.py
```

产出 `data/papers.json`（已评分、已分栏）。抓取量不足时引擎会自动放宽窗口重试，让它自行完成。若网络需要代理：`HTTPS_PROXY=http://…` 前缀。

**若脚本非零退出（网络/接口故障）**：不要继续后续步骤——向用户报告网络异常（已有 `data/papers.json` 不会被覆盖），检查网络或代理后重试。

### 第 2 步：生成待摘要清单

```bash
python3 scripts/render.py plan
```

产出 `outputs/pending-<日期>.json`：当日应精读的 ≤12 篇（已剔除近 7 天推送过的；无摘要/无编号/仅模板的空壳摘要自动滤除；`--top N` 可调）。

### 第 3 步：你逐篇生成中文速览（本 skill 的核心价值）

对 pending 清单里的**每一篇**，读其 `abstract`，按以下规范输出五行结构（写入 `outputs/agent-summaries-<日期>.json`，<日期>与第 2 步 pending 清单同日期；数组元素 `{"pmid": "...", "summary": "..."}`，summary 内用换行分隔五行）：

```
【标题】中文短标题，≤25字，直接点明研究主题
【临床意义】1-2句：对{{DEPT}}临床实践或后续研究的意义；无直接应用就明写"目前无直接临床应用"
【要点】3-4条（分号分隔，单行）：每条15-40字；保留具体数字（样本量/HR/OR/95%CI/P值/随访年限）；药物写通用名，只比较类别时写类别名并注明；样本量写清口径（如"815例患者"）
【证据等级】从枚举中选一个：随机对照试验/荟萃分析/系统综述/综述/队列研究/病例对照/病例报告/基础研究；必须与研究设计一致，综述不得写成队列研究
【谨慎解读】1句，指出最关键的局限
```

**硬约束**：① 每个数字必须来自该篇原文摘要（渲染层校验，不合规打回），**写法与原文逐字符一致**（含千分位逗号、小数位），不做「3.5万」「三千」等换算；② 不编造数据、不补充原文没有的数字；③ 药名/量表自带数字（IL-17、DAS28 等）不受限；④ 全文中文（药名通用名可保留英文原文），总字数 ≤350；⑤ 全部篇目一次生成完毕再进下一步。

### 第 4 步：校验与渲染

```bash
python3 scripts/render.py finalize
```

- 全部通过 → 日报生成于 `outputs/{{SLUG}}-<日期>.md`，向用户报告精读篇数即可
- 有 ❌ 数字保真失败篇目 → 按终端提示**只修正那些篇目**（对照原文摘要改数字），重跑 finalize

## 输出与积累

- 日报：`outputs/{{SLUG}}-<日期>.md`（可直接展示给用户）
- 本地库：`data/digest.db` 逐日积累，支撑跨天去重（同一文献 7 天内不重复精读）
- 在研管线：papers.json 内含 ClinicalTrials.gov 的 Phase 2/3 试验，日报外可单独汇报

## 边界

- 不要修改 scripts/ 下的任何脚本
- 数据只读公共学术 API，不回写任何外部系统
- 用户想加病种/调权重：改 `scripts/specs/{{SPEC_FILE}}`（检索词与期刊权重都在里面）；换科室建议安装系列对应专科包（医学文献日报）
- `--spec` / `CLINICAL_SPEC` 仅作用于抓取阶段；渲染（标题/文件名/入库）按本包 `spec.json` 的科室执行
